# 快捷键与朗读行为设计 v1

本文档定义 Receipt Voice v1 的键盘行为和 TTS 朗读规则。第一版目标是让视障/低视力咖啡师在不依赖鼠标的情况下完成“听单、切商品、切订单、完成、撤销”。

## 设计原则

- 先定义行为，再映射键位。
- 快捷键只在应用窗口获得焦点时生效。
- 输入框、文本域、下拉框和可编辑区域内不拦截快捷键。
- 默认键位尽量避开系统常用键；用户自定义时不做大量限制，由现场训练和键盘贴纸决定。
- 第一版只提供少量高频行为，不追求快捷键数量。
- 商品属性来自 `order_items.item_options`。
- 整单备注来自 `orders.order_note`，朗读商品列表时也必须读出整单备注。

## 默认键位

| 键位 | 行为 |
| --- | --- |
| `1` | 读全文 |
| `2` | 读概览 |
| `3` | 读商品列表 |
| `4` | 上一商品 |
| `5` | 下一商品 |
| `6` | 上一单 |
| `7` | 下一单 |
| `8` | 完成 |
| `9` | 停止朗读 |
| `0` | 语速循环 |
| `Ctrl+Z` | 撤销 |
| `Ctrl+Plus` | 字体放大 |
| `Ctrl+Minus` | 字体缩小 |

键位分组：

```text
1-3  读当前订单
4-5  商品内移动
6-7  订单间移动
8    完成
9    停止朗读
0    语速循环
Ctrl+Plus / Ctrl+Minus  调整字体
```

## 行为定义

### 读全文

读取当前订单的完整制作信息。

朗读内容：

```text
platform
display_no
order_type
pickup_method
location
order_time
所有商品：name、quantity、item_options
order_note
```

示例：

```text
美团 #1，自取，顾客到店自取，1号口袋，预计十一点四十八到店。
经典美式，一份，冷，默认。
整单备注：顾客需要餐具。
```

规则：

- `item_options` 为空时不读“无属性”。
- `order_note` 为空时不读“无备注”。
- 如果订单无法结构化，直接朗读 `orders.raw_text`。

### 读概览

读取当前订单的短播报，用于主动确认当前任务。

朗读内容：

```text
platform
display_no
order_type
pickup_method
location
商品名 + 份数
商品总数
```

示例：

```text
美团 #1，自取，顾客到店自取，1号口袋。经典美式一份。共一项。
```

规则：

- 概览不读 `item_options`。
- 概览不读 `order_note`。

### 切单短提示

上一单、下一单、完成后自动切单、撤销后恢复订单时，默认只读最少确认信息，不读商品。

朗读内容：

```text
display_no
堂食/外卖/外带
MM月DD日HH点mm分
```

示例：

```text
美团 #1，堂食，5月21日11点41分。
银豹 吧台 P0009，外带，6月7日12点40分。
```

规则：

- 日期不读年份。
- 时间只读小时和分钟，不读秒。
- 不读商品名、商品属性、整单备注。

### 读商品列表

只读取商品制作内容，并在最后读取整单备注。

朗读内容：

```text
第 1 项，name，quantity，item_options。
第 2 项，name，quantity，item_options。
...
整单备注：order_note。
```

示例：

```text
第 1 项，经典美式，一份，冷，默认。
整单备注：顾客需要餐具。
```

规则：

- 商品列表必须读 `item_options`。
- 商品列表必须在最后读 `order_note`，因为整单备注可能影响制作或交付。
- `order_note` 为空时跳过。

### 上一商品

商品游标向前移动一项，并朗读移动后的商品。

朗读内容：

```text
第 N 项，共 M 项，name，quantity，item_options。
```

边界规则：

- 如果已经是第一个商品，游标不变，朗读“已经是第一个商品”。
- 如果当前订单没有商品，朗读“当前订单没有结构化商品”，并可提示读全文。

### 下一商品

商品游标向后移动一项，并朗读移动后的商品。

朗读内容：

```text
第 N 项，共 M 项，name，quantity，item_options。
```

边界规则：

- 如果已经是最后一个商品，游标不变，朗读“已经是最后一个商品”。
- 如果当前订单没有商品，朗读“当前订单没有结构化商品”，并可提示读全文。

### 上一单

订单游标移动到上一张待制作订单。

行为：

```text
1. 当前待确认完成状态取消。
2. 当前订单切换到上一单。
3. 商品游标重置到第一个商品。
4. 自动朗读新订单切单短提示。
```

边界规则：

- 队列为空时朗读“当前没有待制作订单”。
- 到第一单继续按时，可以循环到最后一单；第一版默认使用循环。

### 下一单

订单游标移动到下一张待制作订单。

行为：

```text
1. 当前待确认完成状态取消。
2. 当前订单切换到下一单。
3. 商品游标重置到第一个商品。
4. 自动朗读新订单切单短提示。
```

边界规则：

- 队列为空时朗读“当前没有待制作订单”。
- 到最后一单继续按时，可以循环到第一单；第一版默认使用循环。

### 完成

完成当前订单。该行为必须二次确认。

第一次触发：

```text
准备完成 {display_no}。再按 8 确认。
```

第二次触发，且仍是同一订单：

```text
1. orders.status 更新为 done。
2. 写入 order_events.done。
3. 当前订单从待制作队列移除。
4. 自动选中下一单；如果没有下一单，选中上一单。
5. 如果队列还有订单，朗读新订单切单短提示。
6. 如果队列为空，朗读“所有订单已完成”。
```

切换订单后：

```text
待确认完成状态必须取消。
```

### 停止朗读

立即停止当前 TTS。

规则：

- 不改变订单游标。
- 不改变商品游标。
- 不改变完成确认状态。

### 撤销

撤销最近完成的订单。

行为：

```text
1. 找到最近一次完成的订单。
2. orders.status 改回 pending。
3. 写入 order_events.undo_done。
4. 当前订单切换到恢复的订单。
5. 商品游标重置到第一个商品。
6. 朗读恢复订单的切单短提示。
```

边界规则：

- 没有可撤销订单时朗读“没有可撤销的完成记录”。
- 第一版只撤销最近完成的一单。

### 语速循环

在五档语速之间循环。

顺序：

```text
慢速 -> 中速 -> 快速 -> 更快 -> 最快 -> 慢速
```

朗读：

```text
语速已切换为慢速。
语速已切换为中速。
语速已切换为快速。
语速已切换为更快。
语速已切换为最快。
```

设置保存：

```text
app_settings.tts_rate
```

### 字体放大 / 字体缩小

调整工作台字号，不改变订单游标或朗读状态。

顺序：

```text
normal -> large -> xlarge -> xxlarge -> max
```

设置保存：

```text
app_settings.ui_type_scale
```

## 状态游标

UI 需要维护两个游标：

| 游标 | 说明 |
| --- | --- |
| `current_order_id` | 当前选中的待制作订单 |
| `current_item_index` | 当前订单内的商品索引，从 0 开始 |

游标重置规则：

- 切换订单后，`current_item_index = 0`。
- 完成订单后，自动选中新订单，`current_item_index = 0`。
- 撤销订单后，选中恢复订单，`current_item_index = 0`。
- 读全文、读概览、读商品列表不改变商品游标。

## 自定义快捷键

第一版可以先使用默认键位。后续如加入设置页，自定义快捷键应存入：

```text
app_settings.shortcuts
```

值为 JSON 字符串：

```json
{
  "read_full": "1",
  "read_overview": "2",
  "read_items": "3",
  "previous_item": "4",
  "next_item": "5",
  "previous_order": "6",
  "next_order": "7",
  "complete_order": "8",
  "stop_speaking": "9",
  "cycle_rate": "0",
  "undo_complete": "Ctrl+Z",
  "increase_type_scale": "Ctrl+Plus",
  "decrease_type_scale": "Ctrl+Minus"
}
```

自定义限制：

- 除空键位外，单键和组合键都允许绑定，例如 `Tab`、方向键、`Enter`、`Space`、`Alt+1`、`Ctrl+R`。
- 不允许两个行为绑定同一个键位。
- 输入框、文本域、下拉框和可编辑区域内仍然不触发应用快捷键，避免影响设置填写。
- 修改快捷键后需要立即生效，并写入 `app_settings`。
